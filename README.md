# claude-code-statusline

[Claude Code](https://claude.com/claude-code) のステータスライン用スクリプト。画面下部に次を1行で常時表示します。

```
~/my-project │ 5h枠 26%→16:00 │ 週枠 14%→7/10 │ codex週 33%→10/10 │ Pro · Opus 5.5 · 文脈 15/60% · 累計$7.47 · ⚒2
```

5時間制限が無いプラン（アカウント確認済みの Ultra）では、週枠だけが届くので `5h枠` の区画が出ません。

```
~/my-project │ 週枠 14%→7/10 │ codex週 33%→10/10 │ Ultra · Opus 5.5 · 文脈 15/60% · 累計$7.47
```

| 区画 | 意味 |
|---|---|
| `~/my-project` | 現在の作業ディレクトリ。ホームは `~` に短縮、40文字を超える場合は中間ディレクトリを頭文字1字に省略（`~/p/s/src` のように末尾だけ残す） |
| `5h枠` | 5時間ローリングウィンドウのレート制限消費率。`→16:00` はリセット時刻。週枠だけが届いたとき（アカウント確認済みの Ultra など）は区画ごと出ない（後述）。**80% で警告（黄 + `!`）、90% でアラート（赤 + `!!`）** |
| `週枠` | 7日ウィンドウのレート制限消費率。`→7/10` はリセット日 |
| `codex週` | **codex（OpenAI の CLI）の週枠の消費率**。`~/.codex/sessions` の記録から読む。codex を使っていなければ区画ごと出ない |
| `Pro` | サブスクプラン名（Pro / Max / Ultra / Team 等。取得できた時のみ） |
| `Opus 5.5` | 現在使用中のモデル名 |
| `文脈 15/60%` | コンテキスト窓の使用率。`/60%` は autocompact（自動要約）の発火ライン（`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 設定時のみ表示） |
| `累計$7.47` | セッション累計コストの API 料金換算参考値（サブスクリプション利用時は実請求ではない） |
| `⚒2` | **実行中のサブエージェント数**（1件以上あるときだけ表示）。メインがアイドル中も表示を更新するには後述の `refreshInterval` 設定が必要 |

取得できない項目は区画ごと省略されるため、古いバージョンの Claude Code でも動作します（`5h枠` / `週枠` だけは例外で、取得できないと `N/A` と出ます。ただし週枠だけが届いたときは `5h枠` の区画を出しません。後述）。

## 必要環境

- Python 3.9+（標準ライブラリのみ。追加インストール不要。macOS 標準の python3 で動作）

## セットアップ

```bash
cp statusline.py ~/.claude/statusline.py
```

`~/.claude/settings.json` に追記:

```json
{
  "statusLine": {
    "type": "command",
    "command": "python3 ~/.claude/statusline.py",
    "refreshInterval": 5
  }
}
```

`refreshInterval: 5` は、メインがアイドルでバックグラウンドのサブエージェントだけが動いている間もステータスラインを再描画させるための設定です。**これが無いと `⚒N` の点灯・消灯やリセット時刻がイベント発生時までしか更新されません。** `⚒` 表示が不要なら省略して構いません。

autocompact の発火ラインを併記したい場合（任意）:

```json
{
  "env": {
    "CLAUDE_AUTOCOMPACT_PCT_OVERRIDE": "60"
  }
}
```

## しきい値

使用率が **80% で警告**（黄 + `!`）、**90% でアラート**（赤 + `!!`）になります。
色だけだと端末の配色や色覚で見落とすため、記号も付けています。

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `STATUSLINE_WARN_PCT` | `80` | 警告のしきい値 |
| `STATUSLINE_ALERT_PCT` | `90` | アラートのしきい値 |

プログレスバーは出しません。危険度は色が、量は数字が表しており、隣り合うバーは
同じことを二度言っていたためです（枠が3つ並ぶとバーだけで24桁使っていました）。
周辺視野で塗りの長さを見たい場合は、`format_section()` で `make_bar()` を
差し戻せば戻ります（1行）。

## 5h枠が出ない・N/A になるとき

Claude Code の statusLine 仕様では、`rate_limits` の各枠は「API が報告していて、リセット時刻を過ぎていない間だけ」入ります。本スクリプトはプラン名ではなく、**届いたデータで表示を決めます**。

| 届いたデータ | 表示 | 主なケース |
|---|---|---|
| 5h枠・週枠の両方 | 両方を表示 | Pro / Max / Team、アカウント確認前の Ultra |
| 週枠だけ | `5h枠` の区画を出さない | アカウント確認済みの Ultra（2026-10-30 に旧 Max 20x から改称され、確認済みアカウントは5時間制限が撤廃） |
| 5h枠だけ | `5h枠 26%→16:00 │ 週枠 N/A` | 週枠が未報告、またはリセット時刻を過ぎて次の値がまだ届いていない（まれ） |
| どちらも無い | `5h枠 N/A │ 週枠 N/A` | セッション開始直後でまだ応答が無い／API キーや API クレジット（prepaid）課金の組織で使っている／`rate_limits` を渡さない古い Claude Code |

プラン名で決め打ちしないので、アカウント確認前の Ultra のように「Ultra なのに5時間制限が残っている」場合も、届いたとおりに表示されます。
サブスクで使っているはずなのに両方 `N/A` が続くときは、`/login` で組織を選び間違えていないか確認してください（複数の組織に属していて prepaid 側を選ぶと、サブスクの枠ではなく API クレジットを消費します）。

## codex の枠について

Claude の枠は Claude Code が標準入力の JSON で渡してくれますが、codex は別サービスの別プロセスなので
誰も渡してくれません。そこで `~/.codex/sessions/**/*.jsonl` に残る `rate_limits` を読んでいます。

- ステータスラインは短い間隔で繰り返し呼ばれるため、結果を **120 秒キャッシュ**し、探索も更新時刻の新しい 10 本に限っています
- `~/.codex` が無い環境では区画ごと出ません。codex を使っていなければ表示は変わりません
- 消費率は codex 側が記録した値をそのまま出しています（こちらで計算はしていません）

## 実装メモ

- Claude Code は statusLine コマンドの stdin に毎回セッション情報の JSON を渡す。本スクリプトは `workspace.current_dir` / `model` / `cost.total_cost_usd` / `context_window` / `rate_limits`（`used_percentage` と `resets_at`）を参照する
- コンテキスト使用率は `context_window.used_percentage`（v2 系で提供）をそのまま使う。無い旧バージョンでは `transcript_path` の JSONL を走査して直近の usage レコードから推定にフォールバック
- サブスクプラン名だけは stdin に来ないため、`~/.claude.json` の `oauthAccount`（ログイン時にキャッシュされる非公開フィールド）から読む。表示名 `planDisplayName`（例: `Ultra`）を優先し、無ければ枠区分 `organizationRateLimitTier`（例: `default_claude_max_20x` → `Max 20x`）や組織種別から組み立てる。作者の環境では、Ultra に改称された後も枠区分は `max_20x` のままだったため、表示名を優先している。構造が変わって取れない場合は黙って省略
- autocompact 閾値は環境変数 `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` → `~/.claude/settings.json` の `env` の順で読む。「文脈」の色は閾値に対する比率で付く（閾値60で57%ならほぼ満杯＝赤）
- `~/.claude.json` は履歴等で数MBになりうるため、プラン名の解析結果を `~/.claude/statusline-plan.cache` に元ファイルの mtime 付きでキャッシュし、毎レンダリングの全パースを避けている。キャッシュの目印には版（`v2:`）を付けており、解析ロジックを変えた更新後も古い表示が残らない
- 取得できない項目は区画ごと省略する方針（`5h枠` / `週枠` を除く）のため、フィールド構成が違う環境でも1行は必ず出る（想定外の入力・型でも落ちないよう型検証と最終フォールバックを備える）
- サブエージェント数は stdin に来ないため、セッション transcript の隣にできる `<transcript と同名のディレクトリ>/subagents/agent-*.jsonl` のうち mtime が直近30秒以内のものを数える近似。実行中のエージェントは数秒おきに追記するため実用上は一致するが、長いツール実行中は書き込みが止まり一時的に数え漏れることがある

python3 -m unittest test_statusline
